# M16 — Event engine

**Status:** done. Unit: 1538 checks, 0 failures. No new visible UI yet (the Map tab arrives in M17).

## What exists
- **WorldState** (save schema 8, migration v7→8): events done (with week), missed, scheduled follow-ups, cooldowns, leads, opened/closed areas, visit counts.
- **WorldRules**: area status (open / locked / closed, with reasons), fixed events with time windows and priority, random pools (weight, cooldown, season, requires), follow-up scheduling, missed-event sweep with `on_miss` consequences, deterministic picking (same seed/week/slot/area → same event), flag report.
- **Effects usable in any dialogue or event**: `lead`, `schedule` (relative weeks), `unlock_area`, `lock_area` — plus all existing ones (battle, bond, attr…). Events can lead to battle.
- **Game.visit_area(id)**: spends the area's travel cost in slots, plays a due fixed event, a random one, or a short wander (small reward); autosaves.
- **Validator**: unique ids, regions, windows inside 1..180, scene dialogue exists, follow-ups/areas/battles exist, fixed events reachable, every flag that is read is set somewhere, all text keys exist in zh and en.
- **Valley content** (generated by `scripts/gen_world.py`): 5 areas (village, river bend, herb terraces [not winter], abandoned shrine [opened by story], ferry dock [needs a lead]), 6 fixed events with one chain (aftermath → gossip → shrine → ferry rumour), 7 random events (one with a battle, one winter-only).
- **Fuzzer**: 6 seeds × a full 360-slot campaign through the Game API (random visits, random choices, random battle outcomes, save/reload every 40 steps asserting identical state). All reach an ending; no stuck dialogue; every windowed fixed event ends done or missed.

## Found by the fuzzer / tests
- Season lists loaded from JSON are floats; comparison now goes through ints.
- `on_miss` flags were not applied; fixed.
- A follow-up whose parent was missed stays dormant (by design, no dead end).
